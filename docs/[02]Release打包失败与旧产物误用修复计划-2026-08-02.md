## 2. 问题复核

用户执行 `scripts/package-release.ps1` 后没有得到本次开发对应的新程序。日志与文件时间证明：

1. Release 编译在 `CL.exe` 启动前失败，错误为 MSBuild `MSB6001`，进程环境同时出现大小写不同的 `LANG` 和 `lang`，而 MSBuild 使用不区分大小写的字典组装子进程环境，因重复键抛出异常。
2. PowerShell 5.1 的 `$ErrorActionPreference = 'Stop'` 不会自动把所有本机程序的非零退出码转换为终止异常。
3. 脚本执行 `cmake --build` 后没有检查 `$LASTEXITCODE`，因此编译失败后仍进入收集阶段。
4. 收集阶段递归查找任意 `Release` 目录下的 `wpce_ui.exe`，命中了旧构建产物并复制到便携目录。
5. 发布目录中的 `wpce_ui.exe` 时间为 2026-06-30 13:47:08；本批次成功生成的 Debug 程序位于 `build/vs2026-x64-qt/src/ui/Debug/wpce_ui.exe`，时间为 2026-08-02 15:10:19。
6. Windows 构建目标是 `wpce_ui.exe`，不会生成 macOS 使用的 `.app` 包。

## 3. 修复设计

### 3.1 环境规范化

- 在启动 CMake/MSBuild 前移除当前进程中大小写变体的 `LANG/lang`，避免 MSBuild 创建 `CL.exe` 子进程时出现重复环境键。
- 只影响打包脚本进程及其子进程，不修改用户级或系统级永久环境变量。
- 输出明确诊断信息，说明是否发现并清理了冲突变量。

### 3.2 本机命令失败传播

- 增加统一的本机命令调用/退出码检查函数。
- CMake 配置、CMake 构建和 `windeployqt` 任一步返回非零时立即终止并返回失败退出码。
- 失败时不得显示 `Package complete`，不得继续复制或生成启动器。

### 3.3 精确产物定位

- 不再递归选择“第一个 Release EXE”。
- GUI 固定读取：`<BuildDir>/src/ui/Release/wpce_ui.exe`。
- CLI、XPS 过滤器和模拟器分别从其真实构建目录读取；可选产物缺失时给出明确提示，主 GUI 缺失则直接失败。
- 仅在本次构建命令成功后进入产物收集阶段，从逻辑上杜绝旧文件掩盖失败。

### 3.4 发布目录安全

- 不删除 `release/wpce-portable/data`、用户配置或备份文件。
- 覆盖程序和运行库前记录源文件路径、大小和修改时间。
- 打包完成后校验发布 EXE 与构建 EXE 的大小、修改时间和 SHA-256 一致。
- 输出最终可点击/可复制的程序路径：`release/wpce-portable/wpce_ui.exe`。

## 6. 风险与说明

- 当前 Visual Studio 安装路径包含非默认位置，MSVC Redistributable 自动定位仍可能给出警告；该问题与主 EXE 是否生成不同。如果验证时仍无法找到运行库，将记录为独立的便携部署风险，不会伪装为完全自包含。
- Release 全量编译需要一定时间；采用单一明确构建流程，并保留完整退出码和产物校验结果。
- 对发布目录的覆盖仅限可重新生成的二进制和 Qt 依赖，不清空整个目录。
