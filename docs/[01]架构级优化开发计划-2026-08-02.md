## 2. 用户需求理解

本批次包含五个相互关联的目标：

1. 对项目进行整体扫描，实施架构级别优化，而不是仅修复表面问题。
2. 订单和任务单号统一在 `data` 目录下按业务日期分桶，以每日一个权威 JSON 桶保存当日全部任务与订单关联数据。
3. 改善 DWG、DWT 等 CAD 文件在打印程序改写文档名、剥离扩展名或只保留布局名时的识别能力。
4. 修复快速计费小窗编辑数字时，文本被固定列宽、控件边距和步进按钮挤压遮挡的问题。
5. 主窗口与快速计费小窗必须读取同一个计费/订单信息源；任一入口产生的修改都经过同一业务服务，并实时通知另一窗口刷新。
6. 软件业务日期优先使用 PC 系统本地日期；若本地日期无法取得或结果非法，回退到中国区北京时间（UTC+8）。订单号、任务号、日期桶和跨日判断不得各自实现日期逻辑。
7. 外部打印 Job ID 与应用内部 Job ID 必须显式映射并可恢复。订单状态变化、重复监听、程序重启和外部 ID 复用不得生成重复任务或重复订单；任务接收和结算都必须幂等。

关于“每日分桶 JSON”的实现口径，本计划采用以下明确解释：

- 每个业务日期只有一个订单权威桶：`data/YYYY-MM-DD/orders.json`。
- 该文件同时保存当日任务列表、任务单号（`task_id`，与当前 `batch_id` 建立兼容映射）、已结算订单列表及订单和任务的关联。
- 打印捕获原始文件（作业快照、PrintTicket、FixedPage）仍按现有捕获目录保存，不重复塞入订单 JSON；订单桶保存对应 `job_ids` 和必要的冻结计费明细。
- 旧 `_state/today_active.json`、`_state/batches/*/jobs.json`、`_state/settlement_orders/*.json`、`history/YYYY-MM-DD/*.json` 只用于一次性兼容读取和迁移，迁移成功后不再作为运行期双写目标。

## 3. 当前架构扫描结论

### 3.1 已有可复用能力

- `BillingService` 已经承担批次、作业注册表、计价与 Qt 信号通知职责，可作为统一业务入口继续演进。
- `PricingEngine` 已经是矩阵计价的核心实现，主窗口和快速计费窗口无需各自计算价格。
- `BillingBatchRepository` 已具备批次摘要、作业明细、原子替换和旧格式兼容读取能力，可复用其序列化字段与迁移测试。
- `SettlementBridge` 已具备冻结订单、计价配置快照和订单 JSON 往返能力。
- `WatcherBridge` 已将打印线程事件安全地投递到 Qt 主线程，并对高频事件做合并。
- SHD/SPL 补充解析已经能够从影子文件候选字符串中找回原始文档路径，是 CAD 类型识别的关键数据源。

### 3.2 直接影响本次需求的问题

#### 订单存储存在多个事实来源

当前同一业务数据分布在：

- `data/_state/today_active.json`：批次摘要；
- `data/_state/batches/<batch-id>/jobs.json`：批次作业；
- `data/_state/settlement_orders/<order-id>.json`：结算订单副本；
- `data/history/YYYY-MM-DD/<order-id>_*.json`：结算历史副本；
- `data/YYYY-MM-DD/...`：打印捕获数据。

结算会同时写入 `_state/settlement_orders` 和 `history`，历史读取与运行态恢复使用不同目录。双写任一路径失败时，内存仍可能进入已结算状态，形成不一致风险。

#### 主窗口与快速计费窗口写入语义不一致

- 快速计费小窗编辑彩页数后调用 `BillingService::setColorPages()`，会重算价格、更新批次汇总、持久化并发出刷新信号。
- 主窗口的 `CompletionDialog` 允许编辑待定价金额，也提供 `finalPrices()`，但 `MainWindow::onCompleteClicked()` 确认后没有读取或回写这些最终金额，随后直接调用 `BillingService::settle()`。
- 设置中的价格矩阵更新后，仅替换了 `BillingService` 持有的配置指针，没有立即对未结算作业统一重算。

因此现有设计名义上共享模型，实际修改命令并没有统一，最终冻结订单可能与主窗口弹窗显示金额不同。

#### CAD 文件类型识别缺少来源和置信度

- 精确后缀、文档标题标记和应用程序名推断全部返回一个裸字符串，无法区分“SHD 原始路径中的 `.dwt`”和“看到 AutoCAD 字样后猜测为 `.dwg`”。
- SHD 补充只在当前扩展名为空时触发；如果打印链路给出错误或降级后的扩展名，就不会用更可靠的 SHD 原始路径纠正。
- 无后缀的 AutoCAD、BricsCAD、DraftSight 标题统一推断为 DWG，无法区分 DWT。
- 当前测试覆盖 DWG，但缺少 DWT、冲突候选和来源优先级用例。

#### 计费小窗数字编辑器几何空间不足

- 彩页数列固定为 64px。
- `QSpinBox` 同时受到全局 `padding: 5px 8px`、默认上下步进按钮和表格单元格内边距影响。
- 自定义委托未关闭步进按钮、未设置对齐方式，也未覆盖编辑器几何，较多位数或高 DPI 下可用文本区域接近零。

#### 文件过大且职责耦合

- `src/ui/main_window.cpp` 约 66KB：混合窗口构造、XPS 过滤器安装、路径迁移、清理、监听控制和业务操作。
- `src/ui/quick_settle_dialog.cpp` 约 55KB：混合自绘样式、窗口系统行为、导航、编辑器、计费展示和命令转发。
- `src/billing/billing_service.cpp` 约 49KB：混合领域状态、重复作业处理、计价、持久化、迁移加载和 Qt 事件。
- `UserTaskModel`、`UserGroupModel` 与新的 `BillingBatchModel` 同时参与编译，保留两套任务/计费模型概念，后续容易被误用。
- 核心业务服务目前位于 `wpce::ui` 命名空间并依赖 `QObject`，导致核心结算流程缺少直接单元测试；现有 99 项测试中没有覆盖 `BillingService` 的跨窗口一致性和结算写入事务。

### 3.3 本批次暂不扩大处理的风险

- `print_watcher.cpp` 约 71KB，但属于高风险打印监听热路径。本批次只调整与文件类型证据传递直接相关的小范围接口，不做整体拆分。
- 项目内有多套手写 JSON 读写器。本批次会为日订单桶建立集中序列化边界，不全面替换配置、捕获和 PrintTicket 等既有 JSON 实现。
- XPS 过滤器真实驱动安装、签名与不同 CAD 软件的真实打印回归需要管理员环境；自动测试以纯函数、模拟 SHD 数据和现有过滤器测试为主，人工场景作为最终验收项。

## 4. 目标架构

```text
WatcherBridge
    │ 打印快照 / 元数据 / 生命周期
    ▼
BillingService（唯一命令入口、Qt 应用服务）
    │
    ├── BillingLedger（纯 C++ 领域状态与计价编排）
    │       └── PricingEngine（唯一计价算法）
    │
    ├── DailyOrderRepository（唯一订单持久化入口）
    │       └── data/YYYY-MM-DD/orders.json
    │
    └── billingStateChanged(revision/change-set)
             ├── BillingBatchModel → 主窗口
             ├── QuickSettleDialog → 快速计费小窗
             ├── CompletionDialog → 结算草稿编辑
             └── HistoryExplorerDialog → 历史读取
```

设计原则：

- UI 只展示快照和发送命令，不直接计算、冻结或写订单。
- 所有彩页数、人工金额、价格规则变更和结算动作必须先进入同一个业务服务。
- 每次成功变更递增内存版本号 `revision`；两个窗口按批次 ID 和版本刷新，不再依赖可能因排序变化而失效的行号。
- 结算先构造完整日桶新版本并原子落盘，持久化成功后才提交内存状态与发送 `orderSettled`，避免“界面显示已结算但订单文件缺失”。
- 已结算订单是冻结快照，不因后续价格配置变化而重算；未结算任务在配置更新后由服务统一重算并广播。
- 日期统一由 `BusinessClock` 提供：系统本地日期有效时使用本地日期，否则将 UTC 加八小时得到北京时间。禁止在 `MainWindow`、`BillingService`、`CounterStore` 和仓储中分别调用不同日期 API。
- 作业身份分为 `external_job_id` 与 `internal_job_id`。幂等键至少包含打印机、外部 Job ID、提交时间和稳定文档身份；同一幂等键重复进入只做合并更新。
- 订单以任务 ID 作为结算幂等键。任务已有有效 `settle_order_id` 时重复结算直接返回原订单号；仓储对 `order_id` 和已结算 `task_id` 建立双重唯一性检查。

## 5. 每日订单 JSON 设计

目标路径：

```text
data/
  2026-08-02/
    orders.json
    latest/...
    jobs/...
    pages/...
```

建议 schema（字段命名以最终实现为准）：

```json
{
  "schema_version": 4,
  "business_date": "2026-08-02",
  "revision": 12,
  "updated_at_utc": "2026-08-02T08:10:20Z",
  "tasks": [
    {
      "task_id": "B-20260802-000001",
      "batch_id": "B-20260802-000001",
      "display_name": "用户#1",
      "source_user": "DOMAIN\\user",
      "state": "active",
      "job_ids": [101, 102],
      "jobs": [],
      "settle_order_id": ""
    }
  ],
  "orders": [
    {
      "order_id": "SETTLE-20260802-000001",
      "task_id": "B-20260802-000001",
      "batch_id": "B-20260802-000001",
      "job_ids": [101, 102],
      "pricing_entries": [],
      "total_price": 12.50,
      "currency": "CNY"
    }
  ]
}
```

存储规则：

- 一个日期一个 `orders.json`，其中包含当日全部任务及全部结算订单，不再为每张订单创建独立 JSON。
- `task_id` 作为对外任务单号；当前 `batch_id` 在 schema v4 中保留同值字段，避免旧代码和旧数据立即失效。
- 未结算任务保存完整作业记录，保证崩溃恢复；已结算订单保存冻结计费明细和关联作业 ID。
- 写入采用 `orders.json.tmp` + 刷盘 + 原子替换；保留最后一次可读备份，仅在解析失败时启用。
- 迁移器按日期聚合旧历史订单和当日状态；同一 `order_id` 去重，以结构完整度和更新时间选择保留项。
- 迁移成功写入标记后停止旧目录双写；旧文件不自动删除，便于回滚和人工核对。
- 保留策略仍只删除超过期限的日期桶，不删除配置；删除日期桶等同于删除该日捕获和订单历史，界面需沿用现有保留天数设置并明确提示。

## 6. 分阶段实施计划

### 阶段 A：后端、领域与存储（先实施）

1. 新增纯 C++ `BillingLedger`，承接批次、作业、计价调整、状态机和结算草稿验证；`BillingService` 缩减为 Qt 信号/槽和持久化协调外观。
2. 新增 `DailyOrderRepository` 与 schema v4 序列化器，实现按日期加载、原子保存、去重、旧数据迁移和损坏文件保护。
3. 把结算改为事务顺序：验证无待定价项 → 生成订单 → 写入日桶 → 提交领域状态 → 广播刷新。
4. 增加统一命令：设置彩页数、设置/清除人工价格、按新配置重算所有未结算任务、结算任务。
5. `SettlementBridge` 保留订单构造与旧格式读取能力，移除运行期的旧目录双写职责。
6. 历史查询改为枚举 `data/YYYY-MM-DD/orders.json`，不再读取每订单文件。
7. 新增统一 `BusinessClock` 并替换任务号、订单号、目录、跨日检测中的分散日期逻辑；添加 PC 本地日期失败时的北京时间回退测试入口。
8. 扩展作业契约保存外部/内部 ID 与稳定幂等键；持久化映射并在监听事件进入领域层前、领域层接收时各做一次去重。
9. 结算命令增加任务级幂等保护，日桶仓储增加订单号与任务号双唯一约束；重复调用返回第一次成功生成的订单号。

### 阶段 B：文件类型识别（后端功能完成后实施）

1. 从 `pricing_engine.cpp` 提取独立 `FileTypeDetector`，避免文件识别与计价算法耦合。
2. 引入识别结果：规范扩展名、证据来源、置信度和原始候选；候选来源包括 `JOB_INFO_2.pDocument`、通知字段、SHD 原始字符串和应用标题。
3. 采用明确优先级：SHD/完整路径精确后缀 > spooler 文档名精确后缀 > 独立 DWG/DWT 标记 > 应用标题低置信度推断。
4. 支持 `.dwg`、`.dwt` 及设置中已有的其他 CAD 扩展名；AutoCAD 无后缀标题只作为低置信度候选，不覆盖更高置信度的 DWT 证据。
5. 当当前类型缺失、低置信度或与 SHD 冲突时触发补充解析，而不是仅在空值时补充。
6. 序列化识别来源与置信度，便于诊断误判；计价继续只消费最终规范化扩展名。

### 阶段 C：主窗口与计费窗口功能联调（后端稳定后实施）

1. 主窗口、快速计费小窗、完成结算弹窗全部订阅同一个 `BillingService` 状态版本。
2. 快速小窗以 `batch_id` 保持当前焦点，不保存易失效的模型行号。
3. `CompletionDialog` 返回结构化调整命令并在服务中校验/应用，不再丢弃 `finalPrices()`。
4. 两个窗口修改同一任务后，另一窗口实时更新页数、彩页数、待定价状态、合计和结算按钮状态。
5. 设置保存后统一触发未结算任务重算；已结算订单保持冻结。

### 阶段 D：界面与样式优化（最后实施）

1. 修复彩页数编辑器：关闭步进按钮、文本居中、使用局部紧凑样式、覆盖编辑器几何、提高最小列宽并适配 DPI。
2. 将 `main_window.cpp` 中可复用的标题栏、指标卡、工作区面板、工具按钮构造提取为小型 UI 组件/工厂；不在窗口类中继续堆叠内联样式字符串。
3. 将快速结算表格委托、窗口行为和内容渲染拆分，保留现有置顶、折叠、托盘和快捷键能力。
4. 统一 QSS 设计令牌：背景层级、边框、圆角、字号、状态色、焦点态；改善主窗口信息层级、窄窗口布局和高 DPI 可读性。
5. 清理确认未被新架构引用的旧 `UserTaskModel/UserGroupModel` 业务实现；若某些 DTO/委托仍有使用，先迁移到中性文件再从构建目标移除旧模型。

## 8. 测试与验收标准

### 8.1 当前基线

- 2026-08-02 已运行 Qt Debug 构建的完整 CTest。
- 结果：99/99 通过，0 失败。
- 包含：序列化、PrintTicket、DWG 识别、计价矩阵、订单桥接、计数器、1k/2k 压力测试和过滤器流水线。

### 8.2 新增自动测试

- 日桶往返：同日多个任务、多个订单、任务单号与订单号关联完整。
- 跨日隔离：不同日期只读写自己的 `orders.json`。
- 原子失败：写入失败不改变内存结算状态，不损坏上一版文件。
- 迁移去重：旧 `_state` 与 `history` 双份订单只生成一条新记录。
- 损坏保护：非法 JSON 保留原文件并回退到最后可读备份。
- 一致性：主窗口命令与快速窗口命令产生相同的服务状态和冻结订单金额。
- 日期：系统本地日期有效时优先采用；模拟本地转换失败时固定回退 UTC+8；任务号、订单号、目录日期完全一致。
- 作业幂等：同一外部 Job 的重复通知、状态跳变和重启恢复只保留一个内部任务；外部 Job ID 被系统复用但提交身份不同时必须分配新的内部 ID。
- 订单幂等：同一任务连续结算、重复信号结算、落盘成功后的重试均只存在一个订单并返回相同订单号。
- 人工价格：编辑后持久化、刷新、重启恢复和结算冻结均一致。
- 配置重算：价格规则变化只重算未结算任务。

## 9. 风险与回滚策略

- 日桶单文件重写的主要风险是意外中断；通过防抖、临时文件、刷盘、原子替换和最后可读备份控制。
- 旧数据可能存在重复、字段缺失或订单与批次关系不完整；迁移采用只读旧数据、写新桶、不删除旧文件的方式，发现异常可回退到旧读取器。
- 将业务状态从 QObject 服务中抽出会影响调用面；采用外观接口兼容、分小步编译和逐层测试，避免同时改动打印监听热路径。
